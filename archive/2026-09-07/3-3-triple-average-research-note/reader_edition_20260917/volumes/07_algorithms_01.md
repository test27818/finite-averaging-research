# 二平均求解器复核、三平均优化与最短性

日期：2026-09-11。用户提供的 `2-average-solver.html` 已原样复制到工作区根目录。源文件和副本的 SHA256 均为

```text
d71cca94ee272e06b829e4974b8a2f980f49593ae467532418238c6d0d51b76a
```

原 HTML 未作修改。本文分析其算法、复用可迁移部分，并给出三平均最短步数问题的复杂度归约。HTML 内的说明是待核对的材料，不是本次任务的额外指令。

## 1. HTML 实际提供了什么

求解器把四种保证分开：数学可解判定、构造出序列、独立验解、证明该序列最短。这个区分正确。

主要流程为：

1. 用 BigInt 中心化、本原化并排序，消除整体尺度与位置置换对称。
2. 优先消去相反数对、找到零和四元组，或用已有零位置补成二幂块进行蝶形收尾；比较五种块配对顺序，跳过恒等平均。
3. 否则选择本原整数平方和下降的合法操作；若没有，使用有预算的最佳优先搜索逃离当前局部陷阱。
4. 在优化预算内尝试另一条构造路线，n=9..24 使用束搜索，n<=12 使用 IDA* 排除更短深度。
5. 把值操作映回原位置，使用独立有理数验证器重放。

这不是二平均论文的多项式构造算法实现。`construct` 中的逃逸搜索有资源上限，且即使选择不设时间限制仍有 19000 步保护。它能诚实报告可解但构造未完成，没有证明所有输入都能在本实现预算内得到解。

独立验解只验证可行性，不验证“最短已证”标签。最短性由内部下界和 IDA* 的搜索完备性承担；当前导出的 JSON 没有可由第三方小验证器直接检查的完整排除树。因此跨工具复核最短性需要重跑有界搜索或给出另外的数学下界。

没有在本次检查中发现虚假最优标记的具体反例。内置 16 个测试全部通过；另有四个小实例的最短步数同时通过独立 Fraction BFS 对照。

## 2. 二平均的下界为何成立

HTML 记 m 为非零偏差个数，c 为可两两不重叠配成相反数的最大对数，C=ceil(m/2)，使用

\[
h_2=C+\max\left(0,\left\lceil\frac{C-c}{2}\right\rceil\right).
\tag{1}
\]

令 z 为一次解中的抵消操作数，k 为非抵消操作数。只有平均两个非零相反数能够减少非零项，且每次只减少两项，所以 z>=C。

一个抵消操作恰消耗一个相反数对；一个非抵消操作至多新建两个可用对。故 z<=c+2k，于是 k>=ceil((C-c)/2)，得到式 (1)。这是可采纳下界。

IDA* 从 h_2 开始逐层排除。只要深度层完整搜索、去重和剪枝正确，第一次找到的解即最短；中断时只能提高到已完成层对应的下界。束搜索不能承担这个排除结论。

## 3. 三平均可以采用同样的最短性验证框架

三平均的准确有向搜索图采用本原整数零和多重集作为顶点。一次操作先将未选值乘 3，被选三项置为其原始和，再整体除 gcd 并排序。这精确表示有理三平均的射影状态。

当 n>=7 时，可以用 G 判据删除必不可解后继；可以删除恒等平均、合并位置置换对称的后继。**不得把双三重值条件、整数中间精度或能量下降当成全局最短搜索的强制剪枝。** 它们只保证存在某一条解，不保证存在最短解仍留在这个子图。

先用不变量算法取得有限上界 U，再运行 BFS、A* 或 IDA* 排除小于 U 的深度。因此：

- 任意给定可解输入，其最短步数可以通过有限搜索确定。
- 设预算时，可以输出已经证明的区间 [L,U]。
- L=U 时有全局最短证明。
- 这不意味着算法是多项式时间。

本次新增 `work/triple_average_optimal_search.py` 已实现三平均上界构造、精确 IDA*、下界及独立原题有理数重放，并明确区分预算中断和最优完成。

### 3.1 三平均的可采纳下界

令 m 为非零项数，C=ceil(m/3)。令 P 为非零位置中互不相交的零和二元组或三元组的最大数量。二元组可在已有零位置配合下做三平均；定义 P 时暂不要求存在这些零，这只会使下界更保守。

一次零均值操作从非零位置中移去一个零和二元组或三元组，因此 P 至少下降一；一次非零均值操作最多修改三个位置，故 P 至多增加三。若总共有 z 个非恒等零均值操作和 k 个其他操作，则

\[
z\ge C,\qquad z\le P+3k.
\]

从而

\[
\boxed{h_3=C+\max\left(0,\left\lceil\frac{C-P}{3}\right\rceil\right).}
\tag{2}
\]

精确求 P 本身不适合作为大规模廉价启发式。实现中以零和二元组、三元组的总数作为 P 的上界，并截断于 C。使用上界使式 (2) 更弱而仍可采纳；不能以贪心找到的不相交组数替代 P，因为那是下界，可能导致高估距离、错误排除最短解。

精确搜索的原始分支数由 C(n,2) 变为 C(n,3)，比值为 (n-2)/3。例如 n=20 时是 190 对与 1140 个三元组。因此三平均即使平均步数较少，最优性搜索也可能更难。

## 4. 同一个 n，没有固定的二三平均步数关系

比较必须使用两种操作都可解的同一输入。对 n>=7 的非零本原状态，共同可解条件恰为 G=1。

下面四个例子都是 n=7，给出的均为全局最短步数，已通过各自搜索及独立有理数 BFS：

| 输入 | 二平均最短 | 三平均最短 |
|---|---:|---:|
| 1, 1, -2, 0, 0, 0, 0 | 3 | 1 |
| 1, 5, -3, -3, 0, 0, 0 | 3 | 4 |
| -1, 1, 0, 0, 0, 0, 0 | 1 | 1 |
| -3, -2, -1, 0, 1, 2, 3 | 3 | 2 |

所以不存在 T_3<=T_2 的普遍不等式，也不能按每次处理三个而非两个位置，直接乘以 2/3 预测步数。

第二个例子的三平均四步证书（1 基索引）为

```text
3, 4, 5
3, 6, 2
4, 1, 2
5, 3, 6
```

三平均 IDA* 完整排除了三步及以下，搜索共访问 86 个节点；独立 Fraction BFS 也得到距离 4。二平均先平均 1 与 5 得到两个 3，再分别与两个 -3 抵消，共三步。

## 5. 三平均最短步数的强 NP 困难性

下面是本次额外得到的一般复杂度结论，独立于搜索性能实验。

**定理。** 对满足 G=1、整数零和且各坐标均非零的 n 元输入（n 是 3 的倍数且 n>=12），判断能否用至多 n/3 次三平均归零是强 NP 完全问题。这里每个实例都保证有限步可解；困难在于达到最少步数。

### 5.1 最低步数等价于零和三元划分

每个原始非零位置都必须至少被选中一次。一共 n/3 次三平均只有 n 个位置参与名额，所以若 n/3 步完成，每个位置恰被选择一次。于是每次操作必须选取三个尚未改变的原始值，并立即使三者为零。

因此

\[
T_{\min}=n/3
\quad\Longleftrightarrow\quad
\text{原始位置可以划分为零和三元组。}
\tag{3}
\]

### 5.2 从数值三维匹配归约

使用经典强 NP 完全问题 Numerical 3-Dimensional Matching（Garey--Johnson，SP16）：给三个各含 m 个正整数的列表 A、B、C 和目标 S，问能否分成 m 组，每组从各列表取一个且和为 S。总和不是 mS 的实例显然为否；可先检查，所以只需考虑总和为 mS。

取 K 大于全部可能的三个小整数项之和的绝对值，例如

\[
K=10(1+S+\max(A\cup B\cup C)).
\]

编码为

\[
x_i=K+a_i,\qquad y_j=3K+b_j,\qquad z_k=-4K+c_k-S.
\tag{4}
\]

这些数总和为零，且均非零。三个高位标签 1、3、-4 的三项和为零，只有每类各一个的情形；其他组合的高位差至少 K，小整数项无法抵消。因此零和三元组恰好对应 a_i+b_j+c_k=S 的合法匹配。

### 5.3 强制 G=1，同时保持匹配等价

设式 (4) 中数值绝对值最大为 B_0，取 L=10B_0+1，再加入三个数

\[
L,\quad L+1,\quad-2L-1.
\tag{5}
\]

它们总和为零且全部非零。因为其中两项之差为 1，整个输入的坐标 gcd 和差分 gcd 均为 1，所以输入保证可二平均及三平均。

由于 L>2B_0，加入一个新数与两个旧数无法零和；加入两个新数与一个旧数也无法零和，因为任意两个新数的和绝对值至少 L>B_0。因此这三个新数只能彼此组成零和三元组，不改变旧匹配的存在性。

令 n=3m+3。由式 (3)，存在原匹配当且仅当这个保证可解的输入可在 n/3 步内归零。编码数值只按源实例数值的常数倍增长，保持强 NP 困难性。这个特定阈值的证书只有 n/3 个三元组，精确验证为多项式时间，因此属于 NP，定理得证。

这不是声称本项目首次在文献中证明了该复杂度分类；本页给出可独立检查的归约，并以经典 N3DM 的强 NP 完全性为外部前提。

### 5.4 对算法目标的含义

除非 P=NP，不能期待对全部输入用多项式时间求出全局最短序列，甚至不能高效判断是否达到简单下界 n/3。

这完全不妨碍可达性判定为多项式，也不妨碍将来证明“存在某条多项式长度的非最优解”。后两者与求最短是不同任务。

它也解释了为什么三平均的精确零和组装比二平均的直接相反数配对复杂：相反数最大配对可以按值计数直接完成，三元零和的互不相交选择已经能承载三维匹配。

## 6. 仍然值得做的优化

二平均：

- 用已证二平均不变量算法作为完整备用构造，替代把可达性完全交给有预算的逃逸搜索。
- 保留多个零和四元组和蝶形配对候选；当前优先找到的四元组可能阻碍更短整体收尾。
- 搜索状态进一步取全局符号商，缓存后继及下界，合并互不相交操作的交换对称。
- 小状态建立精确模式数据库，提高 IDA* 下界；继续区分可行证书与最优证书。

三平均：

- 将不变量构造作为有保证的上界路线，同时尝试零和三元组、三幂网络和已证小型收尾。
- 最大降幅负责快速压缩数值；零和组合负责减少活跃位置；二者应比较候选，不能认为任何单一贪心都最短。
- 对少量候选做束搜索或短程前瞻，再将最佳解交给 IDA* 排除更短深度。
- 优化时允许离开不变量和一位精度限制；这些限制适合完整备用构造，不适合作为最短性前提。
- 对互不相交零和三元组可用小规模精确覆盖或整数规划。大规模应视为组合优化子问题，不能期待廉价全局最优。

# 双三重值算法的操作序列长度

日期：2026-09-11。本文区分现有选择器、改进选择器、最坏长度证明和有限性能实验。适用主范围为 n>=11 的双三重值直接构造；7、8、10 的独立小维数算法不由本页分析。

后续：[二三平均求解器与最短性](../sources/outputs/algorithms/pair_triple_solver_comparison_and_optimality.md)新增结构化收尾、三平均精确IDA*、同题配对测试及最短步数的强NP困难性归约。最后一项针对求全局最短，不影响本页仍开放的非最优统一多项式长度问题。

## 1. 当前能严格得到的结论

令 X 是整数零和输入，满足对每个非三素因子 q|n 不全同余。令 M=max|x_i|，算法在 E_0=3X 上执行整数操作，最后将同一位置序列用于 X。

对现有算法和下面的最大降幅版本，都有

\[
T\le\min\left\{
\frac92\sum_i x_i^2,
\frac34\sum_{i<j}|x_i-x_j|,
(12n^3L)^{n-2}
\right\},
\tag{1}
\]

其中非零输入的 D=max(E_0)-min(E_0)>=1，L=ceil(log_2(2nD^2))。整数步数可以对右侧取下整。零输入为零步。

第三个界实际上适用于任何固定 n 位置、始终保持整数且不执行恒等操作的三平均序列，与双三重值不变量无关。其意义是：固定 n 时，现有算法的长度已是输入位长的多项式；但指数随 n 增长，所以还不是对可变 n 的统一多项式界。

数值大小界与位长界可以取较小者。这些界都不宣称接近最短操作数。

## 2. 两个直接势能界

### 2.1 平方能量：每步至少下降 2

选中整数 a,b,c，均值 m=(a+b+c)/3 也为整数。非恒等时，三个整数偏差和为零且不全为零，因此

\[
\Delta\Phi=(a-m)^2+(b-m)^2+(c-m)^2\ge2.
\]

全部初始化和最后的终端操作也非恒等，所以从 Phi(3X)=9*sum(x_i^2) 到零的总步数满足 T<=(9/2)*sum(x_i^2)。不需要另外加上三步收尾。

### 2.2 两两距离：改为关于 M 的线性界

定义

\[
\Psi(E)=\sum_{i<j}|e_i-e_j|.
\]

将被选三个值排序为 a<=b<=c。它们之间的两两距离和是 2(c-a)，操作后为零。对每个未选值 z，由凸性

\[
|a-z|+|b-z|+|c-z|\ge3|m-z|,
\]

其余跨位置距离和也不会增加。因此

\[
\Delta\Psi\ge2(c-a)\ge4.
\tag{2}
\]

最后一个不等式使用整数性：跨度 1 的非恒等三元组，其和不能被 3 整除。因此 T<=Psi(3X)/4=(3/4)*Psi(X)，进而

\[
T\le\frac34n(n-1)M.
\tag{3}
\]

这个界明显改善平方数值界，但 M 的位长是 log M，所以单独的式 (3) 仍不是位长多项式界。

Psi 无需两两枚举：若 e_(0)<=...<=e_(n-1)，则 Psi=sum_i(2i-n+1)e_(i)。

## 3. 最大间隙递归：固定维数的位长多项式界

本节不要求安全性或任何重数条件，只要求每一步为非恒等整数三平均。

固定全局位置上界 n 和初始包含区间的长度 D。凸性保证后续全部值仍在这个区间内。记

\[
L=\left\lceil\log_2(2nD^2)\right\rceil,
\qquad A=2+2n^3L.
\]

证明任意至多 k 个位置上的此类序列，都不超过

\[
F_k=(3A)^{k-2}\qquad(k\ge2)
\tag{4}
\]

步。k<=2 根本没有三平均操作，作为基例。

### 3.1 一次跨最大间隙操作带来比例下降

在某一阶段开始时，对当前 k 个值排序，直径记为 R>0。最大相邻间隙 g 至少 R/(k-1)。按此间隙将实际位置分成非空的左右两组。

在首次跨组操作之前，每一步只发生在某一组内部。两组各自的凸包都不扩大，所以初始间隙至少保持为 g。

首次跨组操作的三个值跨度至少 g。对任意三元组跨度 s，有

\[
\Delta\Phi
=\frac{(a-b)^2+(b-c)^2+(c-a)^2}{3}
\ge\frac{s^2}{2}.
\]

令 V=sum(e_i-mean(E))^2 为这 k 个位置的方差和。组内操作和跨组操作都保持这 k 个值的总和。因此，整个阶段的方差损失至少

\[
\frac{g^2}{2}\ge\frac{R^2}{2(k-1)^2}
\ge\frac{V_{\rm start}}{2k(k-1)^2}
\ge\frac{V_{\rm start}}{2n^3}.
\tag{5}
\]

故每次出现跨组操作，当前阶段至少使方差乘以 1-1/(2n^3)。随后重新划分最大间隙。

### 3.2 阶段数量与递归长度

非恒定整数配置总有 V>=1/2：取两个不同整数 a,b，它们对任意均值的平方偏差和至少 (a-b)^2/2。初始又有 V<=nD^2。

因此，发生跨组操作的阶段不超过 1+2n^3*ln(2nD^2)，加上可能没有跨组操作的最后一段，总段数不超过 A。

每一段首次跨组之前，两组分别至多有 k-1 个位置。无论怎样交错执行，它们各自的操作子序列仍是固定位置上的非恒等整数三平均，所以由归纳各至多 F_(k-1) 步。全局约束怎样变化不影响这个界，因为归纳界允许所有整数操作。

于是

\[
T_k\le A(2F_{k-1}+1)\le3AF_{k-1}=F_k.
\]

若整段没有跨组操作，同一上界仍成立。归纳证明完毕。由 3A<=12n^3L，得到式 (1) 的第三个界。

这是对现有实际序列的分析，不是用形式操作替换真实路径，也不需要实现递归分组求解器。

### 3.3 位复杂度含义

如果整数输入的最大位长为 B，则 L=O(B+log n)，所以

\[
T\le\bigl(O(n^3(B+\log n))\bigr)^{n-2}.
\tag{6}
\]

固定 n 时，这已排除步数关于 B 的指数增长；可变 n 时，式 (6) 仍然过大。不能把现有实现的慢样本称为已经证明的位长指数下界。

全过程工作整数的绝对值不超过 3M，位长保持 O(B)。因此若进一步得到统一多项式步数，结合可枚举的单步选择器，也就能得到统一多项式时间构造。

## 4. 位长依赖无法完全消除

固定一个含非三素因子的 n>=11，例如 n=11。令 M 为 n 的正倍数，且 M>n-2，取

\[
X_M=(-M,1^{n-2},M-n+2).
\tag{7}
\]

这是本原整数零和输入，G=gcd(M+1,n)=1。

任何 T 步三平均的输出行，都可写成初始值的非负整数权重和除以 3^T，且整数权重总和为 3^T。对一个值为零的输出行，将两端的权重记为 alpha、gamma，中间 n-2 个位置的权重合计为 beta，得到

\[
M(\gamma-\alpha)+\beta-(n-2)\gamma=0,
\qquad \alpha+\beta+\gamma=3^T.
\]

若 alpha=gamma，就得到 3^T=n*gamma，与 n 含非三素因子矛盾。否则

\[
M\le|\beta-(n-2)\gamma|\le(n-2)3^T.
\]

所以连制造一个零坐标都需要

\[
\boxed{T\ge\left\lceil\log_3\frac{M}{n-2}\right\rceil.}
\tag{8}
\]

这对任何策略成立，允许任意中间三进精度。因而固定非三幂维数下，也不可能有独立于输入位长的统一常数步数上界。

若初始全部偏差都非零，每个位置还必须至少参与一次操作，另有 T>=ceil(n/3)。这些是下界，不能据此宣称上界 O(n log M) 已成立。

## 5. 单步比例下降不成立，但可有很短的准备

取 M=1 mod 3，置 a=-5M、b=6M，考虑十一元配置

\[
E_M=(a^4,a-3,a+3,b^5).
\tag{9}
\]

它满足双三重值不变量，且

\[
\Phi(E_M)=330M^2+18.
\]

只有两个模 3 余类，所以非恒等整数操作只能在 a-3、a、a+3 中选择。操作 (a-3,a,a+3) 会得到非法的两值配置 (a^6,b^5)。其余恰有两种安全选择，分别为 (a-3,a,a) 和 (a,a,a+3)，每个能量降幅都恰为 6。

因此，即使每次选最大安全降幅，也不能保证单步损失 >=Phi/poly(n)：固定 n=11，令 M 趋于无穷即可否定这个命题。

不过执行第一种操作后，产生三份 t=a-1。此时 t 与 b 同余模 3，可以安全平均 (b,b,t)，留下三份 b 并产生新三重值。第二步损失为

\[
\frac23(b-t)^2=\frac23(11M+1)^2.
\]

所以这里两步就能带来固定比例下降。这个例子说明，应研究短阶段的定量下降，而不能要求每一步都大幅下降。

## 6. 改进选择器和实际比较

旧程序按证明分类选择遇到的第一个可行操作。这保证终止，不保证减少步数。

新增最大降幅策略：枚举当前实际值类型的可用三元组，检查整数性、所有受保护素数的不全同余以及双三重值条件，然后选择

\[
\Delta\Phi=a^2+b^2+c^2-(a+b+c)^2/3
\]

最大的一个。显式终端依然直接三步完成。这只枚举下一步，不搜索操作词；正确性和一位精度直接继承不变量定理，但最短性和统一多项式步数尚未证明。

实现用局部计数增量更新重数和模 q 类数，每个候选不复制完整状态。若当前有 m 个不同值，则每步扫描 O(m^3) 个候选，各候选安全检查使用 O(d) 个模余数计数更新。

### 6.1 相同随机题面的配对比较

每组 3 个实例。原始 n 个整数独立均匀抽自 [-2^B,2^B]，中心化、本原化后按判据筛选；不是反向构造。B 是抽样范围参数，规范化后的最大位长可能增加 O(log n)。

| n | B | 原选择器平均步数 | 最大降幅平均步数 |
|---:|---:|---:|---:|
| 11 | 8 | 100.7 | 19.7 |
| 11 | 16 | 604.3 | 35.3 |
| 11 | 32 | 3111.3 | 76.7 |
| 20 | 8 | 598.0 | 34.7 |
| 20 | 16 | 8225.0 | 50.7 |
| 20 | 32 | 三个均在 100000 步截断 | 108.0 |

最后一组最大降幅的实际步数为 98、100、126，单例求解约 0.009--0.011 秒。截断不是不可达判定，也不是原选择器的最终步数。

### 6.2 更大整数

以下每组 2 个独立实例，只运行最大降幅策略。

| n | B | 两个实例的步数 | 单例求解时间范围 |
|---:|---:|---:|---:|
| 11 | 64 | 133、132 | 0.008--0.010 秒 |
| 11 | 128 | 306、268 | 0.022--0.024 秒 |
| 20 | 64 | 222、247 | 0.031--0.033 秒 |

全部完成的路径都用原始未乘 3 的坐标独立 Fraction 重放，逐步检查分母仅为 1 或 3，最终精确归零。时间只计求解，不包括抽样和独立重放。这些数字是本机有限样本，不能证明平均或最坏复杂度阶数。

原始记录保存于 `work/double_triple_length_benchmark.json` 和 `work/double_triple_length_large_benchmark.json`。

## 7. 还缺什么长度定理

值得尝试的下一命题是：存在固定常数 c 和多项式 P(n,B)，使每个满足不变量的非终端状态，都能在 P(n,B) 步内到达终端，或让总能量乘以至多 1-1/n^c。

若证明这一命题，由初始能量的对数为 O(B+log n)，即可得到统一多项式构造长度。它可以通过改进选步实现，不必证明现有任意首个可行策略也满足相同界。

二平均论文第 6 节的策略是按余数类建立定量混合引理，控制何时产生可跨越大间隙的新余数。三平均需要三个模 3 类、多危险支持集与双三重值同时控制。本页的式 (9) 已展示“两步改变余数后进行大跨度操作”的具体机制，但还没有证明统一阶段界。

当前最准确的结论是：判定已是多项式；固定维数的构造长度已有位长多项式界；可变维数的统一多项式构造仍待证明；最大安全降幅是已经实现并验证、有限实验显著更短的选步策略。

## 8. 核验与来源

`work/analyze_double_triple_sequence_length.py` 默认精确核对 69,926 个整数能量和两两距离不等式、150 个最大降幅选择与独立枚举的对照、142 个带组内交错的最大间隙阶段、6 个单步障碍/两步修复实例，以及 23,466 个短输出行的下界排除。

这些检查不承担无限量词；式 (1)、固定维数长度界和式 (8) 的一般证明分别位于第 2--4 节。


# Arena三平均网页算法审阅与同题对比

日期：2026-09-12。审阅对象：[用户提供的网页](https://01a09196-93af-786c-810a-960e700588f5.arena.site/)。

结论：在小整数、零和组合较多的输入上，网页是一个实用的短解启发式，连续运行时确有提速。但相对项目已有的“短宏+结构构造”组合，步数多数相同；其大整数稳定性明显不足，不能作为完整求解算法替代现有构造。最值得采用的是零和子集宏与快速选步，再接严格构造兜底。

## 1. 实际审阅与复现范围

通过无界面的Microsoft Edge实际打开网页，读取内部 iframe 的算法源码，保存[页面快照](../sources/work/arena_triple_solver_review/frame1.html)和[提取的计算部分](../sources/work/arena_triple_solver_review/arena_solver.js)。算法文件没有修改，仅统一换行；[来源与SHA256](../sources/work/arena_triple_solver_review/provenance.json)记录版本。

将已检查的纯计算函数放入Node隔离上下文，排除页面渲染、网络加载和统计脚本，用原网页单题默认参数运行：

~~~text
width=400, depth=70, maxNodes=60000, timeMs=9000, moveCap=60
~~~

另设外部16秒终止保护，以免原网页的预算检查失效。正式48个对比输入均由网页自身返回，没有触发外部终止。各题串行运行，随后再串行复测旧Python算法，避免同时争抢CPU。

复用原有三个数据集：

- 24个独立均匀取自[-20,20]、同时满足二平均和三平均条件的输入，n为11、12、16、20；
- 18个8、16、32位幅度输入，n为11或20；
- 6个64、128位幅度输入，n为11、20、50，由旧大整数数据集各组选取第0个样本。

额外测试整体缩放、已知判定类别和固定宏。所有网页报告成功的索引序列，均由另外的Python Fraction验证器从原始数值重放至精确均值。

没有把随机搜索未命中认定为不可达；样本比较不外推到所有输入。

## 2. 网页的真正算法

它采用以下顺序：

1. 找精确零和三元组，立即消去。
2. 用中间相遇方法寻找4至9元的零和子集，配合已有零位置执行固定宏。
3. 尝试一个准备操作，使下一步能直接消元。
4. 如果仍未归零，运行有宽度、深度和预算限制的束搜索。
5. 解长不超过60时，尝试逐个删除操作；只有从原输入重新验证成功才接受删除。

### 固定宏是最有效的一部分

| 非零子集大小 | 所需额外零位置 | 固定宏步数 |
|---:|---:|---:|
| 4 | 3 | 5 |
| 5 | 2 | 5 |
| 6 | 1 | 5 |
| 7 | 2 | 6 |
| 8 | 1 | 6 |
| 9 | 0 | 6 |

这些宏确实正确。审阅中对每类零和子空间的全部基向量，另外用Fraction重放，共33个基测试通过，因此不是“看起来接近零”的假解。

寻找零和子集时仅使用最多24个非零位置，中间相遇每半至多12项，所以典型规模是每半至多4096个子集。对小值域输入，这能快速一次消去很多位置；它比只降低平方能量更贴近“早日达到精确零”的目标。

项目此前已经采用零和三元组、补零三幂块和四非零项收尾，因此很多小输入会产生同样长度的解。网页的额外4至6元宏和不同子集选取次序，偶尔能进一步缩短。

## 3. 24个小整数同题：确实快，步数改进较小

两边都解出24/24题。与旧的短宏组合算法比较：

- 22题步数相同；
- 1题从19步降到13步；
- 1题从9步变成10步；
- 平均步数从8.46降到8.25。

分维数看：

| n | 旧纯不变量构造的平均步数 | 旧短宏组合 | 网页 |
|---:|---:|---:|---:|
| 11 | 16.17 | 7.00 | 7.00 |
| 12 | 16.33 | 6.50 | 6.50 |
| 16 | 22.33 | 10.50 | 9.50 |
| 20 | 23.67 | 9.83 | 10.00 |

所以如果对比的是更早的纯能量下降，网页的改进很大；如果对比的是已经加入短宏的版本，整体步数改进约2.5%。

### 计时要计入浏览器预热差异

用每题新建JS上下文时，网页平均2.25ms，旧Python短宏组合平均1.95ms。

但用户通常在同一个网页连续求解，因此另做一次固定上下文、先执行3次不计时预热的24题对比，网页平均降到
\[
\boxed{0.85\ \text{ms/题}}
\]
而旧Python约1.95ms。这个场景下网页约快2.3倍，用户的提速体感有依据。

这些是本机实测，不是语言无关的算法复杂度结论。Node/V8的JIT、BigInt实现、Python对象开销都参与了差异；页面绘制、加载、动画与启动开销没有计入算法时间。不能把0.85ms理解为用户点击到页面全部绘制完的耗时。

## 4. 位数提高后的成功率与耗时

后面三组对比的旧基线是“最大安全能量降幅”完整构造，未额外搜索更短解。两种策略目标不同：网页花预算尝试更短路径，旧构造先保证给出可验证的解。

| 输入组 | 题数 | 网页成功 | 旧构造成功 | 网页平均耗时 | 旧构造平均耗时 |
|---|---:|---:|---:|---:|---:|
| 小整数同题 | 24 | 24 | 24 | 0.85ms，预热后 | 1.95ms |
| 8位幅度 | 6 | 6 | 6 | 193ms | 2.04ms |
| 16位幅度 | 6 | 3 | 6 | 4.75秒 | 3.41ms |
| 32位幅度 | 6 | 0 | 6 | 9.30秒 | 6.91ms |
| 64/128位幅度 | 6 | 0 | 6 | 10.48秒 | 86.98ms |

8位组中有5题几毫秒完成，但1题进入约1.14秒的束搜索，所以平均值突然上升。不能只用“8位”假设每题难度相近。

网页成功的8位组平均11.5步，旧构造27.17步。16位组只对网页成功的同3题比较，网页平均14步，旧构造35.33步；没有用成功子集的步数均值冒充全组表现。

一个具体同题：

~~~text
[-191, 162, 107, -16, 42, 58, 38, -148, 41, 123, -29]
~~~

网页7步，最大降幅构造22步，网页在此确实更短。

但旧64位十一元样本能用133步在约9.5ms内构造完成，网页默认预算约8秒返回“未找到”。64/128位尚远未到Number溢出范围，不能把这些失败全归因于溢出；主要问题是小值域精确零和组合减少，束搜索的候选和排名没有充分利用严格的模3及重数结构。

全部48个比较题里，网页解出33题，旧方法解出48题。因此网页目前不适合作为通用求解器唯一后端。

## 5. “全程精确算术”需要更准确地表述

网页的数值更新与最终验证确实使用约分BigInt分数，已经给出的成功解没有发现浮点伪零问题。

但决定搜哪些操作时使用
~~~javascript
Number(numerator) / Number(denominator)
~~~
并据此做近邻定位、排序、容差预筛和评分。因此准确说法应是：

> 状态与验解精确；候选筛选和搜索评分使用浮点启发式。

两个影响已被实际触发：

### 同一题整体放大，会改变解甚至导致漏解

用旧数据集的一道十一元题，保持结构不变，仅乘正数：

| 整体倍率 | 网页结果 |
|---|---|
| 1 | 9步成功 |
| \(10^{30}\) | 10步成功 |
| \(10^{310}\) | 未找到；没有生成任何搜索候选 |

我把原9步索引原封不动作用到两种放大后的输入，都用Fraction精确验证成功。因此不是数学可达性变化，是数值表示和启发式变化。

巨大倍率下Number出现Infinity/NaN，近邻筛选不再正常。网页手动输入并未限制位数，所以这个输入在其接受范围内。简单的连续整数示例在同样倍率下仍可能被固定宏直接解决，故不是“大整数一律失败”，而是需要搜索时容易暴露问题。

### 评分的优先级不随尺度保持

代码使用
~~~javascript
nonzeroCount * 1e12 + distinctCount * 1e6 + sumAbs
~~~
以及带 \(10^{15}\) 常数的异号优先分数。数值变大后，幅度项会压过原本想优先考虑的非零位置数或异号配对，导致排序目标改变。

这可以通过字典序评分或对幅度归一化解决，无需牺牲精确验解。

## 6. 搜索预算和产品行为的限制

预算只在一个外层节点处理结束且
~~~javascript
(nodes & 511) === 0
~~~
时检查。一个外层节点能一次增加多个节点，可能直接跨过512的倍数，因此检查频率不可靠。

实际将预算设为1ms、节点上限10时，函数仍运行约211ms，并生成6112个候选。默认9秒预算的一个大整数样本也运行到14.86秒。主求解的贪心和中间相遇阶段没有统一截止时间。

此外：

- 没有Web Worker，主要计算在页面线程进行；async只在偶尔到达的检查点让出执行。
- 束搜索只保留少量启发式候选，不完整枚举所有三元组；G合法并不保证在预算内能找到路径。
- 搜索状态只按精确有理多重集去重，没有整体本原尺度商，可能重复探索相同射影结构。
- 束搜索阶段没有重新充分调用固定短宏收尾，已有的宏优势主要局限于前置贪心阶段。
- 单题导出包含完整操作；批量结果只保存步数和耗时，未保存各题操作序列，所以批量导出无法独立重放。若按用户原求解器要求，这一项还需补齐。

它明确将预算失败显示为“已判定可行，但未找到”，这一点是正确的。不能把网页显示的成功率当作G判据的成立比例。

随机生成确实是各位置独立抽样再用判据筛选，没有逆向打乱泄露答案。不过使用Math.random与Number取整，只适合普通安全整数值域；不宜声称任意大整数值域都均匀精确采样。

## 7. 最值得整合的改进

建议保留现有算法为快速候选层，顺序如下：

1. 精确零和三元组与中间相遇零和子集，调用已核验短宏；
2. 遇到难题立即保留一个由项目完整构造算法给出的解；
3. 用剩余预算运行束搜索，只有找到更短且验证通过的序列才替换；
4. 在束节点接近终端时尝试短宏收尾，不必再逐原子搜索全部尾段。

同时做四个实现修正：

- 在中心化整数代表上处理精确三元和；用哈希表查第三项，避免Number预筛遗漏。
- 评分采用字典序：非零数、结构特征、归一化能量等，避免固定大常数被输入幅度击穿。
- 用“距离下次检查已新增多少节点”或固定循环计数检测预算，并覆盖所有前置阶段；放入Worker以保持页面可操作。
- 若采用本原化或符号商，只用于搜索与排名，并保存原位置账本；最终仍从原始输入精确重放。

这些改进不会证明最短解，但可以结合网页的小值域速度与项目构造的大整数稳定性。本轮只审阅、对比和保存证据，没有修改线上网页或将试验性启发式替换项目正式求解器。

# 三平均计算的性能审计与搜索优化

本文记录 2026-09-09 对现有计算程序的性能复核、优化依据和新得到的九十一元结果。数学结论的总边界仍以 [最新交接稿](../sources/outputs/triple_average/history/triple_average_research_handoff_2026-09-09.md) 和 [研究勘误](../sources/outputs/triple_average/history/triple_average_research_corrections.md) 为准。

后续 B21 深度五已进一步将主 BFS 状态整数化，并按尺度恢复真实证书；同样八进程的 Fraction 对照为 98.0 秒，整数引擎为 11.2 秒。该任务与下表九十一元不同，不混用性能倍数，详见 [B21 性能复核](../sources/outputs/triple_average/history/triple_average_b21_integer_search_optimization.md)。

## 1. 为什么此前没有占满电脑

测试机器为 Intel Core i5-1035G1，4 个物理核心、8 个逻辑处理器，内存约 16GB，Python 3.11.9。大多数现有程序是单进程 CPython；整数和 `Fraction` 运算受全局解释器锁约束，一个程序通常只持续使用一个逻辑处理器。

此前独立脚本批量核验时曾并行启动多份程序，但耗时最长的 `analyze_n91_terminal_cusps.py --depth 3` 在脚本内部逐尖点串行搜索。因此当时约 541 秒的运行没有使用全部本机算力。这里没有数学上的串行要求，只是原程序没有实现并行调度。

## 2. 性能剖析找到的真正热点

对深度 2 搜索做 `cProfile` 后，剖析运行共 151,199,374 次函数调用、耗时 97.075 秒。其中：

| 函数 | 累计时间 | 占总时间 |
|---|---:|---:|
| `terminal_search` | 96.151 秒 | 99.0% |
| `subset_counts` | 95.527 秒 | 98.4% |

主要成本不是三元组扩展，而是稀疏子集和 DP 对 `Fraction` 的数百万次加法、乘法和哈希。未剖析的原深度 2 运行约 32.663 秒。

## 3. 已实现的等价优化

`search_n91_missing_class.py` 的零和子集检查现在先取所有分母的最小公倍数，把有理数统一缩放为整数，再除去缩放整数的公因子。缩放不改变子集和是否为零；按已选元素数分层的稀疏 DP 还避免了旧实现的二元组键分配。

整个九十一元状态有 91 个元素且总和为零，所以存在 81 元零和子集，当且仅当存在其 10 元零和补集。程序现在搜索大小 10 而非大小 81，并在找到后取补集。27 元和81元目标共用一张整数 DP 表。

`analyze_n91_terminal_cusps.py` 现在把不同尖点交给多个进程，默认使用 `os.cpu_count()` 返回的全部逻辑处理器；`--jobs 1` 保留为串行对照。对单个开放尖点可用 `--cusp 29` 过滤，并用 `--split-depth 2` 固定前两步、生成几十个独立任务。工作进程返回的每条路径和零和见证会在父进程重新执行并检查，避免并行结果未经复核直接写入结论。

新旧 DP 的等价性由 `work/verify_n91_search_optimization.py` 固定核验；它在确定性九十一元 BFS 状态上比较存在性，并重新验证每个命中的元素数、零和及可用重数。这个回归脚本只核验实现等价，不增加搜索结论的证据等级。

## 5. 对六条减暴力建议的核对

### 安全三元组

建议在算法上成立。`verify_isolated_prime_reduction.py` 和 `verify_multi_prime_core.py` 仍直接枚举位置三元组，适合当前 $n\le30$ 的有限实验；若用于大 $n$ 构造，应先用 `Counter` 统计模 3 与危险素数下的类别重数，再枚举可实现的类别三元组。

需要注意，若把所有非三素数直接拼成一个联合签名，类别数可能按素数个数乘法增长。较稳妥的方法是模 3 控制可整除性，并用每个危险素数的少数主类/例外类增量检查安全性。它能加快搜索，但不填补一般安全投影定理。

### 危险边

这项建议已经实现。`verify_power_partition_compression.py` 的回归枚举只枚举两条候选边的并集，当前复杂度正是约 $O(m^4p^4)$，没有枚举 $p^m$。

更强的是，对应证明文档第4节已经完全使用相交边/不相交边的解析论证：当 $t\ge5$ 且块权在 $p\ne3$ 下可逆时，两条危险边会迫使全部块平均相同。因此一般证明根本不需要余数枚举；3,542,820个模式只是实现回归测试。继续把它降到 $O(m^2p^3)$ 只会缩短测试，不会产生新的数学结论。

### 同时分块修复

当前证明本身已经是交换图论证：每个旧素数至多删除 $K_t$ 的一条边，删除少于 $t-1$ 条边后图仍连通，只需为当前素数找到一条允许边和一对不同余数的元素。因此每个素数只执行一次交换，并非组合爆搜。

程序实现仍重复计算块平均并扫描块内位置。缓存各素数的块余数签名、为每个块建立余数到位置的索引，可以降低常数。二分匹配只有在计划同时执行多次交换或优化额外目标时才有必要；若直接替换，必须重新证明匹配中的所有交换共同保持旧素数见证。

### 项目化覆盖

已经实现。七元、十元和十一元证书都先计算 `local_signature`，用 `Counter` 合并同签名余数类，然后每组只做一次精确实根隔离和下降覆盖。十一元的221,184个局部类最终只形成36个签名。

### 五元 BFS

已经实现多重集排序、primitive 约分和全局符号商；而且已经降级为历史有界搜索，不用于宣称全称可达。尚未实现三进 valuation 分层。这个分层只有在证明它与一步平均及随后本原化的转移相容后才能作为状态商，否则可能错误合并可达性不同的状态。

### 一般分块压缩

三幂网络已经是确定的递归张量网络，没有展开成无约束操作树。缓存每个素数的块余数签名和交换后的增量更新是有效工程优化；当前样本规模尚未使它成为主要耗时。其数学缺口仍在压缩后的对数秩核，而不在网络执行。

## 6. 总体判断

所给总体判断属实：已完成小维数具有较强精确证书，一般维数仍不能由有限实验推出。继续扩大无结构暴力搜索的收益有限。最有价值的计算应服务于两件事：寻找并猜测一般链间加权和转移宏，以及识别高秩真实返回群的算术轨道与终端超平面的相交机制。

本次优化本身也说明了这一点：把零和与补集结构写进算法后，速度提高两个数量级，并先把九十一元深度四覆盖从20/24推进到23/24，再用定向深度五搜索完成24/24。结构性化简比单纯增加枚举范围更有效。

# 三平均搜索优化建议复核（2026-09-09）

本文复核外部提出的六条“减少暴力搜索”建议，并说明它们在当前项目中的适用层次。运行时以项目根目录的 Python 3.11 为准。

## 结论先行

此前九十一元深度搜索没有占满本机，是程序调度方式造成的：深度 3 的旧实现把尖点逐个交给单进程 CPython。当前版本默认使用 `os.cpu_count()` 个进程；在本机 Intel i5-1035G1（4 核、8 线程）上，存在性优先 DP 的深度 3 约 2.2 秒、深度 4 约 14.2 秒（同一程序的旧整数 DP 基准分别约 6.3 秒和 118 秒）。新的 `--cusp` 和 `--split-depth` 允许只搜索开放尖点，并把一个尖点的前两步拆成几十个独立任务。

这类加速只改变计算证书的获得速度，不改变证据等级。深度 5 定向搜索已把已知同余容器内 24 个合法尖点全部覆盖，但容器是否等于真实正向宏群，以及任意输入能否进入该二维核，仍未证明。

## 六条建议逐项判断

### 1. 按余数类别生成安全三元组

方向正确，但“安全”必须分成两个条件：

* 三元组和模 3 为零，保证平均后的坐标仍为整数（若允许有理状态，这一条件可放宽）；
* 对每个危险素数 (p\ne3)，删除三元组后剩余坐标不能全同余模 (p)。

因此可以先用 `Counter(value % 3)` 和每个危险素数的余数类重数生成候选类别三元组，再在类别中选择实际位置。不能把所有非三素数余数直接拼成一个联合签名后宣称复杂度恒定：联合类别数会按素数个数乘法增长。模 3 类别控制加上危险素数的主类/例外类增量检查更稳健。

当前 `verify_isolated_prime_reduction.py` 与 `verify_multi_prime_core.py` 为有限核验，仍枚举位置三元组；它们的样本规模 (n\le30) 尚未使这部分成为主要耗时。建议把类别生成器作为新实验模块，不能直接替换证明中的全称安全引理。

### 2. 危险边的并集枚举与解析判定

这条建议已经落地。`verify_power_partition_compression.py` 的危险边回归测试只枚举两条边的端点并集，复杂度约为 (O(m^4p^4))，没有展开成 (p^m)。数学证明更强：当块数 (t\ge5) 且 (p\ne3) 时，两条相交或不相交的危险边都会迫使所有块平均相同，和已有合法性见证矛盾，所以每个旧素数最多禁一条边。交换图删去少于 (t-1) 条边后仍连通，遂可逐素数各做一次交换。

继续把回归枚举压到 (O(m^2p^3)) 只会缩短测试时间，不会补出新的数学结论；证明本身已经不需要余数穷举。

### 3. 同时分块修复和二分匹配

交换图证明已经给出“每个素数一次交换”的构造，不存在逐块对的组合爆搜。程序层面仍可缓存：

1. 每个素数下的块平均签名；
2. 每个块中“余数到位置”的索引；
3. 交换后的块平均增量。

二分匹配适合需要同时执行多次交换、或有额外优化目标的版本。若只为保留旧素数见证而直接替换成匹配，必须证明匹配中的所有交换共同不触发危险边；现有单交换证明不能自动推出这一点。

### 4. 按 `local_signature` 分组

这条已经落地。七元、十元、十一元的有限覆盖先按局部签名分组，再对每组做一次根隔离和下降判定。十一元的 221,184 个局部类压缩为 36 个签名。它是确定的缓存/商空间优化，但签名必须保留证明所需的全部局部数据，不能为节省状态数而删除可达性信息。

### 5. 五元 BFS 的规范化和三进 valuation 分层

多重集排序、primitive 约分和全局符号商已经用于历史有界 BFS；该程序只寻找短见证，不能用于宣称全称可达。三进 valuation 分层只有在证明“平均一步 + 随后本原化”在该商上定义良好的转移后才能合并状态。否则两个同层状态可能拥有不同的可达边，错误的商会把不可达性抹掉。这个建议目前属于待证明的状态压缩，而不是可直接开启的安全优化。

### 6. 三幂分块递归网络

递归三进网络已经按层实现，没有展开无约束操作树。对一个 (3^k) 块，网络的实际平均次数为 (k3^{k-1})；层数是 (k)，两者不能混为同一个复杂度。缓存块余数签名和交换后的增量是合理的工程优化，但当前样本的主要成本在二维核的零和子集判定，而不是网络执行。

## 九十一元搜索的新入口

```text
python work/analyze_n91_terminal_cusps.py --cusp 29 --depth 5 --jobs 8 --split-depth 2
```

其中 `--cusp` 可重复指定尖点编号；`--split-depth 2` 将每个候选尖点的前两步固定后再并行搜索；父进程会重新执行每条返回路径并检查零和见证。`--split-first` 是深度一拆分的简写。没有指定筛选时，原有的 24 尖点覆盖流程仍保持不变；深度 4 的全量流程仍用于复现 `23/24` 基准。

零和子集内核还做了两项等价优化：统一分母后除去整数公因子，并先按“已选元素数”分层做存在性 DP，只有命中目标时才回溯一个见证。独立核验脚本在确定性九十一元 BFS 状态上逐项与旧版 `Fraction` DP 对照，并检查所有新见证的大小、零和及可用重数；九十一元代表状态的两步证书仍由独立重放确认。

## 证据边界

所有 `PASS` 都只表示相应脚本的声明性检查成功。搜索中的 `OPEN` 表示给定深度内未找到见证，不表示不可达。当前最值得继续投入的是：一般高重数桥的统一证明，以及真实返回宏群和有限同余容器之间的群论等式。

## 1. 当前可复核性判断

在本指南建立之前，项目的数学总览已经较清楚，但验证工程不足以让陌生 AI 可靠接手：`work/` 中 124 个文件平铺混放，没有根目录入口、机器可读映射或统一命令；部分结论文档只列脚本名而未说明证据边界；`verify_*` 同时包含精确有限证书、随机样本和有限深度搜索。

现在新增了三层入口：

1. 根目录 `README.md` 给出阅读顺序；
2. `work/verification_manifest.json` 逐项记录结论、状态、文档、脚本、结构化命令、输出标记、证据范围和运行档位；
3. `work/run_verifications.py` 校验清单并统一运行。

现有历史文件没有移动。新核验者可以快速上手，但仍必须阅读每项的 `does_not_establish`，不能把程序 PASS 自动升级为整篇定理的形式化证明。

## 3. 证据等级

| 等级 | 可以据此声称 | 不能据此声称 |
|---|---|---|
| `theorem-certificate` | 一个已明确归约为有限问题的证书被精确复算 | 证明文档中的一般归约也已被形式化 |
| `symbolic-check` | 所列精确恒等式、宏和参数实例成立 | 有限参数自动推广到任意参数 |
| `finite-sanity` | 当前实现通过有限穷举或固定种子样本 | 带无限量词的定理由实验得到证明 |
| `exploratory-search` | 在给定界内找到或未找到见证 | `OPEN` 类不可达，或搜索已经完备 |

统一运行器中的 PASS 表示“退出码为零且全部预期标记出现”。对开放搜索，PASS 只表示预期的开放结果被重现。

## 6. 九十一元必须分成三层

九十一元最容易发生证据越界，必须区分：

1. `n91-congruence-container`：`cyclotomic_congruence.py` 精确得到含模 8 条件的已知容器。输出为 21,504 个标签、96 个尖点和 24 个合法尖点。它不证明真实宏群等于该容器。
2. `n91-corrected-witness`：`search_n91_missing_class.py` 验证 $(u,v)=(1,-3)$ 时单独坐标为 $-54$，并给出两步到 27 元零和块的真实证书。它只处理一个代表。
3. `n91-cusp-depth4`：`analyze_n91_terminal_cusps.py --depth 4` 在容器的 24 个合法尖点中覆盖 23 个。深度 3 时开放的尖点 30、32、35 已找到四步证书，只剩尖点 29 为 `OPEN`。这个标记表示深度 4 内未找到证书，并不表示不可达。
4. `n91-cusp29-depth5`：对 `cusp 29 = (-13,18)` 使用 `--cusp 29 --depth 5 --jobs 8 --split-depth 2`，得到五步终端证书；已知容器的有限深度覆盖因此达到 `24/24`。它仍是探索性有限搜索。

脚本默认 `--depth 2`，输出 `covered legal cusps 14 / 24`；深度 3 输出 `20 / 24`；深度 4 输出 `23 / 24`；单独的 cusp 29 深度 5 输出 `covered requested cusps 1 / 1`。整数子集和 DP 与八进程优化后，深度 3 从 540.794 秒降至 6.322 秒，深度 4 从 117.891 秒降至当前约 14.2 秒；新的存在性优先 DP 下，cusp 29 深度 4 约 6.2 秒、深度 5 约 272.8 秒。详见 [计算性能审计](../sources/outputs/algorithms/triple_average_computation_performance_audit.md)。

旧九十一元群路线仍有两项独立缺口：特定正向宏群是否等于同余容器，以及任意输入如何进入其(81,9,1)核。覆盖容器24个尖点本身仍不能省略它们。但整体91元可达判据现已由 odd-composite-factor-closure 的7*13真实因子归约另行完成，不能再将旧群路线的开放状态写成91元未解。

## 8. 本次审计发现并修正的复现问题

1. 九十一元覆盖数现在与搜索深度绑定：默认深度 2 为 `14/24`，深度 3 为 `20/24`，深度 4 为 `23/24`；单独搜索 cusp 29 的深度 5 已得到最后一条证书，清单同时保留深度 4 全量命令和深度 5 定向命令。
2. [三幂分块压缩](../sources/outputs/triple_average/history/triple_average_power_partition_reduction.md) 曾记录 1,055,056 个危险边模式，而当前脚本实际稳定输出 3,542,820；文档已按当前程序修正。
3. 总纲原来只列关键脚本名，未说明一项证明可能依赖多个程序，也未区分精确证书、有限实验和开放搜索；现在以机器清单为唯一运行索引。

后续每次修改验证程序时，应让预期输出变化导致统一运行器失败，并同步更新清单与对应数学文档。这样“脚本变了但旧数字仍留在论文中”的偏差会在复核时直接暴露。

新增 shape-changing-integer-potential：形状变化整数检查点势。整数检查点记录 E=sum x_i^2；已有两步重叠造零和碰撞增大背景公式作为局部宏实例。此条是框架整理，不宣称全局宏存在性或 N(p)<=3p。

shape-potential-literature-interface 已转为支持材料；修正2006计数公式及适用含义，加入Balandraud定理和已读勘误。不以打印成功消息充当证书。

旧 single-value-zero-sum-conjecture 已被 p=13、0^32 1^4 2^4 否定；现有核验改检查反例、最优界 N-floor((p-1)/3) 和三步极端族，不再使用打印占位命令。

EGZ截断分类已更正：对任意 N>=2p-1，无混合p项零和时，至多两个重桶；双重桶覆盖全池，单重桶外的至多p-1个例外必须零和自由。

撤回不必要的 N<4p 上限；正确分类对任意 N>=2p-1 成立。
