# 本项目的接手与研究规则

这是数学研究项目。不要把最新文件、有限实验或旧文中的“仍未解决”直接当作当前数学状态。

## 开始工作前

1. 先读 `knowledge/START_HERE.md` 和 `knowledge/STATUS.md`，再进入对应主题页。
2. 对拟研究的问题运行 `python knowledge/project_knowledge.py context "关键词"`。中文、英文别名与旧路线名都要检索；必要时再用 `rg` 查正文。检索输出不能替代阅读原证明。
3. 阅读最相关的现有结论、限制和后续替代项。在首次研究记录中写清“已有内容／真正需要新增什么／会复用哪些证明与脚本”。查不到答案时，记录查过的入口，不要断言以前没人做过。
4. 数学断言以精确的量词和原证明为准。`knowledge/catalog.json` 管理导航与阶段状态，不是形式化证明；生成索引不构成独立审核。

## 必须区分

- p 或 q 表示平均元数，n 表示位置数；旧三平均文稿中的 p 有时是位置数。
- 已证可达性、改进证明的目标、构造长度、最短路径、静态简洁判据是不同任务。
- 完整一般证明、精确有限证书、恒等式检查、有限搜索是不同证据。PASS 不扩大证据范围。
- 原位置正向词、核心上的射影作用、形式群、有限模像不能免费互换。
- 合数 GRH 条件须保留。未得到反例不等于定理；未搜到路径不等于不可解。

## 写入和更新

- 复用现有结论卡 ID。确有新的定理或独立证明时才新增技术稿；纯状态更新应修改主题页所依赖的结论卡，不再另建一篇“最新总体总结”。
- 新研究默认放 `research/`。保留原证明、证书、历史文件和旧路径；修改已完成证明仅在用户任务明确需要时进行。目录导航的更新不改变数学证据。
- 新结果必须更新 `knowledge/catalog.json` 中：范围、状态、未证明内容、前提／相关结果、替代关系和核验入口。没有程序的书面证明应明写“无独立脚本”，不虚构核验。
- 声称后续替代旧结论时写明替代的具体字段或前提，不能把一篇旧文整篇作废。新研究“本地已给证明”不等于已独立审核或已纳入原主证明。
- 外部来源记录版本、实际读取章节、定理前提、适用代入、未读范围及本地证据路径。
- 完成一轮后执行 `python knowledge/project_knowledge.py check`；有意改动已登记来源后核对其结论卡，再执行 `python knowledge/project_knowledge.py accept-sources <ID...>` 和 `python knowledge/project_knowledge.py build`。不要批量确认未读过的变更。
- 不把 `research/.../README.md`、根 README 或 `work/README.md` 再写成按日期追加的长日志。当前状态只有一个登记源，专题视图由它生成；历史经过保存在原文及整理快照中。

## 交接

交接须包含：本轮实际新增、采用的假设、原证明与计算证据、未完成的精确命题、下一步所需增量。用 `knowledge/SESSION_TEMPLATE.md`。无需用户充当外置记忆来重复提供本项目已有信息。
